## Остановка потока

### stop() — нельзя

`stop()` мгновенно обрывает поток в любой точке: если он писал файл или запись в БД, данные останутся повреждёнными, а мониторы — отпущенными посреди операции.

:::outdated "Thread.stop() больше не работает"
В видео `stop()` перечёркнут, но ещё срабатывает. **С Java 20 `Thread.stop()` всегда бросает `UnsupportedOperationException`.** Методы `suspend()`/`resume()` (пауза/возобновление) тоже выведены из употребления. Единственный правильный способ — кооперативная остановка через `interrupt()`.
:::

### interrupt() — вежливая просьба

`interrupt()` лишь устанавливает потоку **флаг прерывания**. Поток сам должен его проверять и решать, как завершиться:

```java
Thread counter = new Thread(() -> {
    for (int i = 0; i < 1_000_000; i++) {
        if (Thread.currentThread().isInterrupted()) {
            System.out.println("Меня прервали на " + i);
            break;
        }
        System.out.println(i);
    }
});
counter.start();
Thread.sleep(10);
counter.interrupt();
```

Если поток в этот момент **спит** (`sleep`), **ждёт** (`join`, `wait`) или блокирован на очереди, метод сразу бросает `InterruptedException`, а флаг **сбрасывается**.

## sleep() и обработка InterruptedException

```java
Thread timer = new Thread(() -> {
    try {
        int seconds = 0;
        while (true) {                          // весь цикл внутри try
            System.out.println(seconds++);
            Thread.sleep(1000);
        }
    } catch (InterruptedException e) {
        System.out.println("Таймер остановлен");
    }
});
```

Если обернуть в `try` только `sleep`, исключение будет поймано, но цикл продолжится — поток «не услышит» просьбу остановиться ({{t j2 1:19:35}}).

:::warning "Не глотайте InterruptedException"
Если вы ловите `InterruptedException`, но не можете завершить работу прямо здесь (например, в библиотечном методе), **восстановите флаг**: `Thread.currentThread().interrupt();` — иначе вызывающий код не узнает о прерывании. Пустой `catch` — классическая ошибка ревью.
:::

## join() — дождаться потока

```java
List<Integer> list1 = new ArrayList<>(), list2 = new ArrayList<>();
Thread t1 = new Thread(() -> { for (int i = 0; i < 1_000_000; i++) list1.add(i); });
Thread t2 = new Thread(() -> { for (int i = 0; i < 1_000_000; i++) list2.add(i); });
t1.start(); t2.start();

t1.join();      // главный поток ждёт t1
t2.join();      // …и t2
System.out.println(list1.size() + " " + list2.size());   // 1000000 1000000
```

`join()` останавливает **тот поток, в котором вызван**, до завершения потока, **у которого вызван**. Есть вариант с таймаутом: `t.join(500)` или `t.join(Duration.ofSeconds(1))` (Java 19+).

## Порядок потоков не гарантирован

`start()` у трёх потоков подряд не значит, что они выполнятся в этом порядке: `1 3 2`, `2 1 3` — любой вариант. Если поток B зависит от результата A, синхронизируйте их явно (`join`, `CountDownLatch`, `Future`…), а не надейтесь на порядок запуска.

## Жизненный цикл потока

| Состояние (`Thread.State`) | Когда |
|---|---|
| `NEW` | Создан, `start()` ещё не вызван |
| `RUNNABLE` | Выполняется или готов к выполнению |
| `BLOCKED` | Ждёт монитор (`synchronized`) |
| `WAITING` | `join()`, `wait()` без таймаута |
| `TIMED_WAITING` | `sleep()`, `join(ms)`, `wait(ms)` |
| `TERMINATED` | `run()` завершился — перезапустить нельзя |

## Разбор задачи: массив в двух потоках

```java
static final int SIZE = 10_000_000, HALF = SIZE / 2;

static void withConcurrency() throws InterruptedException {
    float[] arr = new float[SIZE];
    Arrays.fill(arr, 1f);
    long before = System.currentTimeMillis();

    float[] a = new float[HALF], b = new float[HALF];
    System.arraycopy(arr, 0, a, 0, HALF);
    System.arraycopy(arr, HALF, b, 0, HALF);

    Thread t1 = new Thread(() -> calc(a, 0));
    Thread t2 = new Thread(() -> calc(b, HALF));    // смещение индекса!
    t1.start(); t2.start();
    t1.join(); t2.join();

    System.arraycopy(a, 0, arr, 0, HALF);
    System.arraycopy(b, 0, arr, HALF, HALF);
    System.out.println("С потоками: " + (System.currentTimeMillis() - before) + " мс");
}

static void calc(float[] part, int offset) {
    for (int i = 0; i < part.length; i++) {
        float f = i + offset;
        part[i] = (float) (part[i] * Math.sin(0.2f + f / 5) * Math.cos(0.2f + f / 5) * Math.cos(0.4f + f / 2));
    }
}
```

:::warning "Тонкость, которой нет в видео"
Во второй половине индекс `i` начинается с нуля, а в однопоточной версии там были значения `5 000 000…`. Чтобы результаты обоих методов совпадали, передавайте **смещение** (`offset`). Проверьте: `Arrays.equals(result1, result2)`.
:::

:::tip "Как правильно замерять время"
`System.currentTimeMillis()` — «настенные часы», их может подвести перевод времени. Для замеров используйте `System.nanoTime()`. А для честных бенчмарков — **JMH** (учитывает прогрев JIT): первые запуски в JVM всегда медленнее.
:::
