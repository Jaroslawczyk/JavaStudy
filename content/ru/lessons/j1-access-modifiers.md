## Четыре уровня доступа

| Модификатор | Внутри класса | В том же пакете | В наследнике (другой пакет) | Везде |
|---|:---:|:---:|:---:|:---:|
| `private` | ✓ | — | — | — |
| *(не указан)* — default / package-private | ✓ | ✓ | — | — |
| `protected` | ✓ | ✓ | ✓ | — |
| `public` | ✓ | ✓ | ✓ | ✓ |

`protected` разберём в уроке о наследовании.

## Проблема открытых полей

```java
Man man = new Man("Иван", 27);
man.age = -40;      // ничто не мешает записать бессмыслицу
```

Если поле `public`, любой код может положить туда что угодно — и объект окажется в некорректном состоянии. Решение: **закрыть поля** и дать доступ через методы.

## Геттеры и сеттеры

```java
public class Man {
    private String name;
    private int age;

    public Man(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() {          // getter — только чтение
        return name;
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {      // setter — запись с проверкой
        if (age > 0) {
            this.age = age;
        } else {
            System.out.println("Возраст должен быть больше нуля");
        }
    }
}
```

- **Getter** — публичный метод без параметров, возвращающий значение поля: `getName()`, `getAge()`. Для `boolean` принято `isActive()`.
- **Setter** — публичный метод, устанавливающий значение: `setAge(int age)`. Главное преимущество — **проверка** перед записью.
- Нет сеттера — поле **только для чтения** (`name` выше).

<kbd>Alt+Insert</kbd> → *Getter*, *Setter* или *Getter and Setter* — IDEA сгенерирует их за секунду.

## Инкапсуляция

Автомобилем управляют педалями и рулём, а не тросом газа и карбюратором. Банкомат выдаёт деньги через кнопки, а не через открытый шкаф с купюрами. **Инкапсуляция — сокрытие реализации**: класс прячет внутреннее устройство и открывает только понятный, безопасный набор методов.

:::tip "Правило"
Все поля — `private`. Вообще всё, что может быть `private`, делайте `private`. Открывайте (`public`) только то, что действительно нужно пользователям класса.
:::

## Пакеты и import

**Пакет** — папка для классов со схожим назначением. Первая строка файла указывает пакет:

```java
package com.example.shop.model;

import com.example.shop.util.PriceFormatter;   // класс из другого пакета
import java.util.List;

public class Product { … }
```

- Классы из своего пакета и из `java.lang` (`String`, `Math`, `System`…) доступны без `import`.
- <kbd>Alt+Enter</kbd> на красном имени класса → *Import class*. Неиспользуемые импорты IDEA показывает серым — удаляйте их (<kbd>Ctrl+Alt+O</kbd> — Optimize Imports).
- Если модификатор не указан (**default**), элемент виден только внутри своего пакета. Поэтому, переложив `Box` в другой пакет, автор получил ошибку `Box is not public`.

## Что не рассказано в видео

### Как называют пакеты

Пакеты называют **обратным доменным именем**: `com.google.gson`, `org.springframework.web`, `pl.mycompany.bank`. Только строчные буквы. Структура внутри — по функциональности (`order`, `payment`, `user`) или по слоям (`controller`, `service`, `repository`).

### Модификаторы классов

Класс верхнего уровня может быть только `public` или default. `private` и `protected` бывают только у вложенных классов (см. статью [Вложенные классы](#/extra/nested-classes)).

### Сеттер лучше бросает исключение, чем печатает

В видео сеттер выводит сообщение в консоль и молча оставляет старое значение. В реальном коде вызывающая сторона так не узнает об ошибке. Правильнее:

```java
public void setAge(int age) {
    if (age <= 0) {
        throw new IllegalArgumentException("Возраст должен быть больше нуля: " + age);
    }
    this.age = age;
}
```

### Не каждому полю нужен сеттер

Генерировать getter + setter «на всё подряд» — частая ошибка: тогда инкапсуляция лишь формальная. Лучше давать **осмысленные** методы: не `setBalance(...)`, а `deposit(...)` и `withdraw(...)`. А поля, которые не должны меняться, делайте `final` и не давайте сеттеров вовсе.

### Lombok и records

- **Lombok**: `@Getter`, `@Setter`, `@Data` генерируют методы при компиляции — очень распространён в Spring-проектах.
- **record**: поля автоматически `private final`, а методы доступа называются как поля: `person.name()`, без `get`.

### Модули (Java 9+)

Над пакетами есть ещё уровень — модули (`module-info.java`), которые решают, какие пакеты вообще видны другим модулям. Подробно — в статье [Modules](#/extra/modules).

:::task hard "Проверка доступа на практике"

??? Подсказка

:::
