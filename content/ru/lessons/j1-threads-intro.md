## Поток и задача

- **`Runnable`** — интерфейс с одним методом `run()`: **что** нужно сделать.
- **`Thread`** — поток выполнения: **кто** это сделает.

```java
Thread timer = new Thread(new Runnable() {
    @Override
    public void run() {
        try {
            int i = 0;
            while (true) {
                System.out.println(i++);
                Thread.sleep(1000);          // уснуть на 1 секунду
            }
        } catch (InterruptedException e) {
            System.out.println("Таймер остановлен");
        }
    }
});
timer.start();                               // запустить в отдельном потоке

for (int i = 0; i < 5; i++) {
    System.out.println("Главный поток работает");
}
```

- `start()` создаёт **новый поток** и вызывает в нём `run()`. Вызов `run()` напрямую просто выполнит код в текущем потоке — частая ошибка новичков.
- Код в `main` выполняется в **главном потоке**, остальные — побочные. Вывод потоков перемешивается непредсказуемо.
- `Thread.sleep(ms)` бросает **проверяемое** `InterruptedException` — его обязательно обработать.

:::tip "Почему try вокруг всего цикла"
Если обернуть в `try-catch` только `Thread.sleep`, то после прерывания поток поймает исключение и… продолжит цикл. Прерывание (`interrupt()`) — это просьба остановиться, поэтому правильно выйти из цикла: обернуть цикл целиком (как в видео) или проверять `Thread.currentThread().isInterrupted()`.
:::

## Общая переменная двух потоков

```java
public class Main {
    private static volatile boolean isFive = false;   // в видео без volatile — см. ниже

    public static void main(String[] args) {
        Thread timer = new Thread(() -> {
            for (int i = 0; ; i++) {
                System.out.println(i);
                if (i == 5) isFive = true;
                sleepSecond();
            }
        });
        Thread timer2 = new Thread(() -> {
            while (!isFive) {
                System.out.println("второй таймер");
                sleepSecond();
            }
        });
        timer.start();
        timer2.start();
    }

    private static void sleepSecond() {
        try {
            Thread.sleep(1000);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}
```

Локальную переменную метода нельзя менять из анонимного класса/лямбды (только effectively final), поэтому флаг вынесен в поле класса — и `static`, потому что используется из статического `main`.

:::warning "Видео не говорит о volatile"
Без ключевого слова **`volatile`** нет гарантии, что изменение `isFive` в одном потоке **станет видно** другому: поток может закэшировать значение, и цикл `while (!isFive)` никогда не завершится. На маленьких примерах это «случайно работает», а в продакшене приводит к зависаниям. Правило: переменная-флаг, которую пишет один поток и читает другой, должна быть `volatile` (или `AtomicBoolean`). Подробно — в разделе о многопоточности части 2 и в статье [JMM и volatile](#/extra/jmm-volatile).
:::

## Что не рассказано в видео

### Лямбда вместо анонимного класса

`Runnable` — функциональный интерфейс, поэтому:

```java
Thread t = new Thread(() -> System.out.println("Работаю в " + Thread.currentThread().getName()));
t.start();
t.join();     // подождать завершения потока
```

### Современная многопоточность

| Подход | Когда |
|---|---|
| `new Thread(...)` | Учебные примеры, редко в реальном коде |
| `ExecutorService` / пулы потоков | Стандарт для серверных задач (часть 2 курса) |
| **Виртуальные потоки** (Java 21+) | Тысячи и миллионы лёгких потоков для I/O-задач: `Thread.ofVirtual().start(task)` или `Executors.newVirtualThreadPerTaskExecutor()` |
| `CompletableFuture` | Асинхронные цепочки задач |

Статья [Virtual Threads](#/extra/virtual-threads) — про главное изменение Java 21.

Создайте два потока: первый — таймер, каждую секунду выводит, сколько секунд прошло; второй пытается **угадать** число, генерируя случайные числа. Когда число угадано, таймер останавливается, а загаданное число выводится на экран. Используйте общую `boolean`-переменную. {{t j1 5:42:56}}
??? Подсказка

:::task hard "Гонка за счётчиком"
Создайте статическое поле `int counter`. Запустите 4 потока, каждый 100 000 раз выполняет `counter++`. После `join()` выведите результат — почему он меньше 400 000? Исправьте тремя способами: `synchronized`-метод, `AtomicInteger`, разделение работы без общего состояния (каждый поток считает своё, затем сложить). Сравните время.
??? Подсказка
`counter++` — это три операции (прочитать, прибавить, записать). Два потока могут прочитать одно и то же значение, и одно увеличение «потеряется». Это называется **состояние гонки** (race condition).
:::
