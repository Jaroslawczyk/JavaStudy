**Сериализация** — превращение объекта в поток байтов (чтобы сохранить в файл или передать по сети), **десериализация** — обратный процесс. Разбираем `Serializable`, `ObjectOutputStream`/`ObjectInputStream`, правила для полей и родителей, `transient`, `Externalizable` и `serialVersionUID` — частые вопросы на собеседованиях. И важное дополнение: почему встроенную сериализацию сегодня почти не используют.

## Сериализация и десериализация

```java
public class User implements Serializable {
    @Serial
    private static final long serialVersionUID = 1L;

    private String name;
    private int age;
    private transient String password;     // не сохраняется
    // конструктор, геттеры, toString
}

// запись
try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("users.bin"))) {
    out.writeObject(new User("John", 25, "secret"));
}

// чтение
try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("users.bin"))) {
    User user = (User) in.readObject();    // ClassNotFoundException, IOException
    System.out.println(user);              // password = null
}
```

## Правила (их спрашивают)

1. Класс реализует **`Serializable`** (интерфейс-маркер, без методов) или `Externalizable`. Иначе — `NotSerializableException`.
2. Все поля тоже сериализуемы (`String`, примитивы, `ArrayList` и т. д.) **или** помечены `transient`. Сериализуется весь граф объектов по ссылкам.
3. `transient`-поля при восстановлении получают значения по умолчанию: `null`, `0`, `false`. `static`-поля не сериализуются вообще — они принадлежат классу.
4. Если **родитель не сериализуем**, у него должен быть доступный конструктор без параметров: при десериализации он вызывается для «несериализуемой части», а её поля не восстанавливаются ({{t j2 6:43:41}} — имя и фамилия стали `null`).
5. **Конструктор сериализуемого класса не вызывается** — объект собирается напрямую из байтов.

:::note "Поправка к видео"
Автор говорит, что «компилятор смотрит на номер версии». Сравнение `serialVersionUID` выполняет не компилятор, а JVM **во время десериализации**. Если номер не объявлен явно, он вычисляется из структуры класса (поля, методы, интерфейсы), поэтому любое изменение класса ломает чтение старых данных: `InvalidClassException: local class incompatible`.
:::

## serialVersionUID

```java
@Serial                                           // Java 14: компилятор проверит объявление
private static final long serialVersionUID = 1L;
```

- Объявляйте **всегда явно** в сериализуемых классах — иначе ID зависит от компилятора и малейшего изменения класса.
- Совместимое изменение (добавили поле) — оставьте номер; новое поле при чтении старых данных получит значение по умолчанию.
- Несовместимое (поменяли тип поля) — увеличьте номер, чтобы старые данные явно отклонялись.

## Serializable vs Externalizable

| | `Serializable` | `Externalizable` |
|---|---|---|
| Методы | нет (маркер) | `writeExternal`, `readExternal` |
| Кто пишет данные | JVM автоматически | вы вручную |
| Конструктор при чтении | не вызывается | вызывается **public без параметров** |

Промежуточный вариант — приватные методы `writeObject(ObjectOutputStream)` / `readObject(ObjectInputStream)` в `Serializable`-классе: можно дописать к автоматической сериализации свою логику (шифрование, проверку инвариантов).

:::warning "Встроенная сериализация опасна"
Десериализация недоверенных данных — одна из самых известных уязвимостей Java: подобранный поток байтов при `readObject()` может выполнить произвольный код через цепочки классов из библиотек на classpath (gadget chains). Архитекторы Java называли сериализацию «ужасной ошибкой». Если всё же нужна — используйте **фильтры десериализации** (`ObjectInputFilter`, Java 9; фабрика фильтров — Java 17, JEP 415) и никогда не читайте объекты из сети/от пользователя без них.
:::

:::outdated "Что используют вместо Serializable"
- **JSON** (Jackson, Gson, JSON-B) — REST API, конфиги, хранение;
- **Protocol Buffers, Avro** — компактные бинарные форматы для сервисов и Kafka;
- **records** сериализуются безопаснее: при чтении вызывается канонический конструктор с его проверками.

Знать `Serializable` нужно для собеседований и старого кода (RMI, кэши, сессии), но в новом коде выбирайте явный формат данных.
:::
