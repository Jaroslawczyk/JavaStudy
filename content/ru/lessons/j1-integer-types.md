## Примитивные типы Java

| Категория | Типы |
|---|---|
| Целые числа | `byte`, `short`, `int`, `long` |
| Числа с плавающей точкой | `float`, `double` |
| Символы | `char` |
| Логический | `boolean` |

Все остальные типы (`String`, массивы, ваши классы) — **ссылочные**, о них позже.

## Целочисленные типы

| Тип | Размер | Диапазон | Когда используют |
|---|---|---|---|
| `byte` | 1 байт | −128 … 127 | Работа с файлами, сетью, бинарными данными |
| `short` | 2 байта | −32 768 … 32 767 | Почти никогда (экономия памяти в огромных массивах) |
| `int` | 4 байта | −2 147 483 648 … 2 147 483 647 (≈ ±2,1 млрд) | **По умолчанию** для целых чисел |
| `long` | 8 байт | ≈ ±9,2 × 10¹⁸ | Большие числа: время в миллисекундах, ID, деньги в копейках |

Точные границы есть в константах: `Integer.MAX_VALUE`, `Integer.MIN_VALUE`, `Long.MAX_VALUE`, `Byte.MIN_VALUE` и т.д.

```java
byte b = 120;
short s = 3_500;
int i = 950_000;
long l = 9_000_000_000L;   // L в конце — литерал типа long
```

:::warning "Суффикс L"
Число, записанное в коде, по умолчанию имеет тип `int`. Литерал больше 2,1 млрд без суффикса `L` — ошибка компиляции `integer number too large`. Пишите заглавную `L`: строчную `l` легко спутать с единицей.
:::

## Переполнение (overflow)

Если результат не помещается в тип, Java **не сообщает об ошибке** — значение «заворачивается» на другой конец диапазона:

```java
byte b = 127;
b++;
System.out.println(b);          // -128

int big = Integer.MAX_VALUE;    // 2147483647
System.out.println(big + 1);    // -2147483648
```

Это как счётчик пробега в старой машине: после 999 999 идёт 000 000. Так устроено хранение чисел в **дополнительном коде** (two's complement).

## Разбор задачи из видео: свет за N дней

```java
int days = 1000;
int speed = 300_000;                  // км/с
int seconds = days * 24 * 60 * 60;    // 86 400 000 — помещается в int
long distance = speed * seconds;      // ОШИБКА ЛОГИКИ: результат отрицательный!
```

Почему `distance` отрицательный, хотя он `long`? Выражение `speed * seconds` вычисляется **в типе `int`** (оба операнда `int`), переполняется, и только потом испорченное значение расширяется до `long`.

**Исправление** — сделать хотя бы один операнд `long` *до* умножения:

```java
long distance = (long) speed * seconds;   // приведение до умножения
// или
long distance = 300_000L * seconds;       // литерал long
```

:::tip "Правило"
Тип результата арифметического выражения — самый «широкий» тип среди операндов (но не уже `int`). Поэтому порядок важен: `(long) a * b` — верно, `(long) (a * b)` — уже поздно, переполнение произошло внутри скобок.
:::

## Приведение типов (type casting)

### Автоматическое (расширяющее)

Меньший тип безопасно превращается в больший — без потери данных:

```text
byte → short → int → long → float → double
           char ↗
```

```java
byte a = 10;
int b = a;       // OK, автоматически
long c = b;      // OK
```

### Ручное (сужающее)

Больший тип в меньший — только явно, ответственность на программисте:

```java
int a = 15;
byte b = (byte) a;        // 15 — поместилось
int big = 300;
byte broken = (byte) big; // 44 — лишние биты отброшены!
```

## Что не рассказано в видео

### Арифметика byte и short всегда даёт int

```java
byte x = 10, y = 20;
byte sum = x + y;          // ОШИБКА: x + y имеет тип int
byte sum2 = (byte) (x + y); // OK
x += 5;                    // OK! составные операторы делают приведение сами
```

### Защита от переполнения

Методы `Math.addExact`, `Math.multiplyExact`, `Math.toIntExact` бросают исключение вместо «тихого» неправильного результата:

```java
long distance = Math.multiplyExact((long) speed, seconds);
int safe = Math.addExact(Integer.MAX_VALUE, 1);   // ArithmeticException: integer overflow
```

### Если не хватает даже long

Для произвольно больших целых чисел есть класс `java.math.BigInteger` (а для точных дробных — `BigDecimal`):

```java
BigInteger factorial = BigInteger.ONE;
for (int n = 2; n <= 50; n++) {
    factorial = factorial.multiply(BigInteger.valueOf(n));
}
System.out.println(factorial);   // 30414093201713378043612608166064768844377641568960512000000000000
```

### Другие системы счисления в литералах

```java
int hex = 0xFF;          // 255 — шестнадцатеричная
int bin = 0b1010_1010;   // 170 — двоичная
int oct = 017;           // 15 — восьмеричная (ведущий 0 — ловушка!)
```

### Целочисленные обёртки

У каждого примитива есть класс-обёртка: `Integer`, `Long`, `Byte`, `Short`. Они нужны для коллекций и содержат полезные методы, например `Integer.parseInt("42")`. Подробно — в уроке об обёртках.

## Домашнее задание

В видео отдельного задания нет — автор советует попрактиковаться с приведением типов. Вот задачи для этого.

:::task easy "Таблица диапазонов"
Выведите минимальное и максимальное значение для `byte`, `short`, `int` и `long`, используя константы `MIN_VALUE` / `MAX_VALUE` классов-обёрток.
:::

:::task easy "Почини программу про свет"
Перепишите программу из видео так, чтобы расстояние, которое свет проходит за 1000 дней, было посчитано верно. Ответ: 25 920 000 000 000 км.
:::

:::task medium "Поймай переполнение"
Посчитайте `Integer.MAX_VALUE * 2` тремя способами: «как есть» в `int`, с приведением к `long` и через `Math.multiplyExact`. Объясните каждый результат.
??? Подсказка
В `int` получится `-2`: 2 147 483 647 × 2 = 4 294 967 294, что на 2³² больше, чем помещается, поэтому результат «завернулся».
:::

:::task hard "Факториалы"
Выведите факториалы чисел от 1 до 25 в типе `long`. Найдите первое `n`, на котором результат становится неверным (подсказка: проверяйте, что `fact / n == предыдущий`), затем перепишите вычисление на `BigInteger`.
??? Подсказка
20! = 2 432 902 008 176 640 000 ещё помещается в `long`, а 21! — уже нет. Циклы разберём через урок — если пока трудно, вернитесь к этой задаче после урока о циклах.
:::
