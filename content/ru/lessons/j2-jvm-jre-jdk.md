## От исходника до выполнения

```
Main.java ──javac──▶ Main.class (байткод) ──JVM──▶ машинный код процессора
```

1. **`javac`** (компилятор) проверяет код и переводит его в **байткод** — набор инструкций для виртуальной машины, одинаковый для всех ОС и процессоров.
2. **JVM** загружает классы (`ClassLoader`), проверяет байткод (verifier) и исполняет его.
3. Один и тот же `.class`/`.jar` запускается на Windows, Linux, macOS, x86 и ARM — нужна только JVM под платформу. Это и есть **WORA** — write once, run anywhere.

### Интерпретатор и JIT

Видео говорит, что JVM «преобразует байткод в машинный код». Как именно:

- Сначала байткод **интерпретируется** — медленно, но старт мгновенный.
- JVM считает, какие методы вызываются часто («горячие»), и **JIT-компилятор** (C1, затем оптимизирующий C2) превращает их в оптимизированный машинный код прямо во время работы — с учётом реального поведения программы (инлайнинг, удаление лишних проверок).
- Поэтому Java-программа «разгоняется» после старта (прогрев, warm-up), а долгоживущие серверы на Java работают очень быстро.

Также в JVM живут **сборщик мусора** (GC), управляющий кучей, потоки, модель памяти.

## JDK, JRE, JVM

| | Что это | Для кого |
|---|---|---|
| **JVM** | Виртуальная машина: исполняет байткод, JIT, GC | — |
| **JRE** | JVM + стандартная библиотека классов | запустить программу |
| **JDK** | JRE + инструменты: `javac`, `java`, `jar`, `jshell`, `javadoc`, `jlink`, `jcmd`, `jfr`… | разработчик |

:::interview "Вопрос с собеседования"
**Чем отличаются JDK, JRE и JVM?** — JVM исполняет байткод. JRE = JVM + библиотека классов — достаточно для запуска. JDK = JRE + инструменты разработки (компилятор, отладка, профилирование). Стоит добавить: с Java 11 отдельный JRE больше не распространяется — ставят JDK или собирают свой рантайм через `jlink`.
:::

:::outdated "Устарело: «JVM есть почти на каждом устройстве»"
Во времена апплетов Java ставили на каждый компьютер отдельно, и автор говорит, что JVM «установлен по умолчанию практически везде». Сегодня это не так:
- **Отдельного JRE нет с Java 11.** Oracle и другие вендоры поставляют JDK; публичная «Java для браузера» исчезла вместе с апплетами (Applet API удалён в Java 26).
- Приложение поставляют **вместе с рантаймом**: Docker-образ с JDK, `jlink` (урезанный рантайм только с нужными модулями, десятки МБ), `jpackage` (установщик `.msi`/`.dmg`/`.deb`).
- **GraalVM Native Image** компилирует программу заранее (AOT) в нативный файл без JVM: старт за миллисекунды, мало памяти — популярно для микросервисов и CLI. Плата — дольше сборка и ограничения на рефлексию.
- JVM ускоряют старт и без AOT-файлов: CDS-архивы и **Project Leyden** (AOT-кэш с Java 24–25).

Какой JDK выбрать — в статье [JDK](#/tools/jdk).
:::

## Что не рассказано в видео

- **Байткод можно посмотреть:** `javap -c Main.class`. Видно инструкции стековой машины: `iload`, `iadd`, `invokevirtual`…
- **Другие языки на JVM:** Kotlin, Scala, Groovy, Clojure компилируются в тот же байткод и используют ту же библиотеку — поэтому JVM называют платформой, а не только «машиной для Java».
- **Запуск без компиляции:** с Java 11 можно `java Main.java` (компиляция в памяти), с Java 22 — программы из нескольких файлов.
- **Память JVM:** куча (объекты, GC), стеки потоков (локальные переменные, вызовы), Metaspace (метаданные классов). Флаги `-Xmx`, `-Xms`.

## Домашнее задание

В видео заданий нет — практика своими силами.

:::task easy "Компиляция вручную"
Без IDE: напишите `Hello.java`, скомпилируйте `javac Hello.java`, запустите `java Hello`. Затем запустите сразу `java Hello.java`. Найдите файл `.class` и посмотрите его байткод `javap -c Hello`.
:::

:::task medium "Прогрев JIT"
Напишите метод, считающий сумму квадратов 1–10 000 000, и вызовите его 20 раз подряд, замеряя `System.nanoTime()`. Постройте график времени по итерациям. Повторите с флагом `-Xint` (только интерпретатор) и `-XX:+PrintCompilation`. Объясните результат.
:::

:::task hard "Свой маленький рантайм"
Сделайте модульное приложение (`module-info.java`, зависит только от `java.base`), соберите рантайм `jlink --add-modules … --output myjre`, сравните размер `myjre` с полным JDK и запустите программу через `myjre/bin/java`. Бонус: соберите установщик через `jpackage`. Подробнее о модулях — [JPMS](#/extra/modules).
:::
