## Что такое ООП

Объектно-ориентированное программирование — подход, в котором программа строится из **объектов**: каждый объединяет данные (поля) и поведение (методы) и взаимодействует с другими через их публичный интерфейс. Класс — «чертёж», объект — экземпляр по этому чертежу.

## Инкапсуляция

**Сокрытие реализации** и защита состояния объекта: данные меняются только через методы, которые соблюдают правила.

```java
public class BankAccount {
    private long balance;                       // снаружи не изменить напрямую

    public void deposit(long amount) {
        if (amount <= 0) throw new IllegalArgumentException("Сумма должна быть > 0");
        balance += amount;
    }
    public long getBalance() { return balance; } // только чтение — сеттера нет
}
```

В Java инкапсуляция достигается модификаторами доступа (`private`, package-private, `protected`, `public`) и [модулями](#/extra/modules). Пример из видео: водитель пользуется рулём и педалями, не управляя напрямую подачей топлива.

:::tip "Инкапсуляция ≠ геттер и сеттер на каждое поле"
Если у каждого поля есть публичный сеттер, объект ничего не защищает. Давайте методы с **смыслом** (`deposit`, `withdraw`), а не `setBalance`. Неизменяемые объекты (`record`, `final`-поля) — самая сильная инкапсуляция.
:::

## Наследование

Класс-наследник получает поля и методы родителя и добавляет свои: `class Lion extends Feline`. Общие черты кошачьих — в родителе, уникальные — у льва, тигра, кота. В Java класс наследует **только один** класс, но реализует любое количество интерфейсов.

## Полиморфизм

**Один интерфейс — множество реализаций**: код работает с общим типом, а поведение определяется реальным объектом во время выполнения (динамическое связывание).

```java
interface Employee { void work(); }
class Programmer implements Employee { public void work() { System.out.println("Программист пишет код"); } }
class Cook implements Employee { public void work() { System.out.println("Повар готовит"); } }

List<Employee> staff = List.of(new Programmer(), new Cook());
for (Employee e : staff) e.work();     // один вызов — разное поведение
```

Виды полиморфизма: **переопределение** (runtime, как выше) и **перегрузка** (compile-time — один метод с разными параметрами). Подробнее о связывании — в статье [Static vs dynamic binding](#/extra/binding).

## Абстракция — четвёртый принцип

Видео называет три принципа, но во многих источниках и на собеседованиях их **четыре**: добавляется **абстракция** — выделение существенных характеристик объекта и отбрасывание несущественных. Интерфейс `Employee` — абстракция: нам важно, что сотрудник умеет `work()`, а не то, как устроен его рабочий день. Назовите все четыре — это никогда не будет ошибкой.

:::interview "Вопросы с собеседования"
**Перечислите принципы ООП.** — Инкапсуляция, наследование, полиморфизм (+ абстракция).

**Приведите пример полиморфизма из жизни.** — Автомобиль: интерфейс один (руль, педали), а реализация — разная: дорогая машина едет мягче и быстрее дешёвой.

**Композиция или наследование?** — «Предпочитайте композицию наследованию»: наследование жёстко связывает классы и ломается при изменении родителя; композиция (объект содержит другой и делегирует ему) гибче. Наследование — когда действительно «является» (is-a) и соблюдается принцип подстановки Лисков.
:::

## SOLID (не из видео, но спрашивают уже на Junior+)

| Буква | Принцип | Коротко |
|---|---|---|
| **S** | Single Responsibility | У класса одна причина для изменения |
| **O** | Open/Closed | Открыт для расширения, закрыт для изменения (новое поведение — новым классом) |
| **L** | Liskov Substitution | Наследника можно подставить вместо родителя без сюрпризов (квадрат — не прямоугольник с сеттерами) |
| **I** | Interface Segregation | Много маленьких интерфейсов лучше одного «толстого» |
| **D** | Dependency Inversion | Зависеть от абстракций, а не от конкретных классов (основа DI в Spring) |

Ещё полезно знать: **DRY**, **KISS**, **YAGNI** и основные паттерны GoF (Singleton, Factory, Builder, Strategy, Observer, Decorator — последний вы уже видели в потоках ввода-вывода).

## Домашнее задание

В видео заданий нет — практика.

:::task easy "Инкапсулированный счёт"
Перепишите класс с публичными полями `balance` и `owner` так, чтобы баланс нельзя было сделать отрицательным, а владельца — изменить после создания. Напишите тесты на запрещённые операции.
:::

:::task medium "Полиморфизм вместо switch"
Есть метод `double area(String type, double… params)` с большим `switch` по типу фигуры. Перепишите на интерфейс `Shape` с методом `area()` и классы-реализации. Добавьте новую фигуру — сколько мест в коде пришлось изменить до и после?
:::

:::task hard "Нарушения SOLID"
Дан класс `OrderService`, который сам валидирует заказ, считает скидку через `if (customer.type == VIP)`, сохраняет в БД через `new MySqlRepository()` и отправляет письмо через `new SmtpClient()`. Найдите нарушения каждой буквы SOLID и отрефакторьте: выделите интерфейсы `DiscountPolicy`, `OrderRepository`, `Notifier`, передавайте зависимости через конструктор и покройте сервис тестами с фейковыми реализациями. О внедрении зависимостей — [DI](#/extra/dependency-injection).
:::
