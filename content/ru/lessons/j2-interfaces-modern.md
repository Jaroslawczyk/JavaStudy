Что можно хранить в интерфейсах, а что нельзя: `default`-методы, статические методы, константы, наследование интерфейсов — и главный вопрос собеседований: **чем абстрактный класс отличается от интерфейса**. Плюс то, что появилось после Java 8: `private`-методы и `sealed`-интерфейсы.

## default-методы

Интерфейс `Car` используют сотни классов. Добавить в него абстрактный метод `stop()` — значит сломать **все** реализации (и лямбды: интерфейс перестал быть функциональным). Решение Java 8 — метод с реализацией по умолчанию:

```java
@FunctionalInterface
public interface Car {
    void go();

    default void stop() {                       // реализация по умолчанию
        System.out.println("Car stopped");
    }
}

Car car = () -> System.out.println("Car goes");  // по-прежнему лямбда
car.go();
car.stop();
```

Именно так в Java 8 в `Collection` добавили `stream()`, `removeIf`, `forEach`, не сломав миллионы классов.

### Конфликт default-методов

Если класс реализует два интерфейса с одинаковым `default`-методом, компилятор требует переопределить его явно и, при желании, вызвать нужный:

```java
class Amphibian implements Car, Boat {
    @Override public void stop() { Car.super.stop(); }
}
```

Правила: метод класса (или суперкласса) всегда побеждает `default`; более конкретный интерфейс побеждает родительский.

## Поля и статические методы

```java
public interface Car {
    int MAX_SPEED = 200;                   // на самом деле public static final

    static void printSpeed() {             // Java 8: вызывается Car.printSpeed()
        System.out.println(MAX_SPEED);
    }
}
```

- Любое поле интерфейса автоматически **`public static final`** — это константа, состояния объекта интерфейс не хранит. Имена — `UPPER_SNAKE_CASE`.
- Статические методы интерфейса **не наследуются** реализациями: только `Car.printSpeed()`.
- Интерфейс может расширять несколько интерфейсов: `interface Car extends Serializable, Comparable<Car>`.

## Абстрактный класс vs интерфейс

| | Абстрактный класс | Интерфейс |
|---|---|---|
| Смысл | Общая **сущность** родственных классов («является») | **Контракт**, поведение («умеет») |
| Состояние (поля экземпляра) | ✅ любые | ❌ только константы |
| Конструкторы | ✅ | ❌ |
| Методы с реализацией | ✅ любые | `default`, `static`, `private` (Java 9) |
| Модификаторы методов | любые | `public` (и `private` с Java 9) |
| Наследование | только **один** класс (`extends`) | сколько угодно (`implements`) |
| Пример JDK | `InputStream`, `AbstractList` | `Serializable`, `Comparable`, `Runnable` |

:::interview "Вопрос с собеседования"
**Когда выбрать абстрактный класс, а когда интерфейс?** — Интерфейс — по умолчанию: описывает возможность, которую могут иметь несвязанные классы, и не ограничивает наследование. Абстрактный класс — когда у семейства классов есть общее **состояние** и общий код, а классы действительно родственны (шаблонный метод). Часто сочетают: интерфейс `List` + скелетная реализация `AbstractList`.
:::

## Что появилось позже

:::outdated "Интерфейсы после Java 8"
- **`private`-методы** (Java 9) — общий код для нескольких `default`-методов, не видимый снаружи.
- **`sealed`-интерфейсы** (Java 17) — список разрешённых реализаций:

```java
public sealed interface Shape permits Circle, Square {}
record Circle(double r) implements Shape {}
record Square(double side) implements Shape {}

double area = switch (shape) {            // pattern matching (Java 21): компилятор проверит полноту
    case Circle c -> Math.PI * c.r() * c.r();
    case Square s -> s.side() * s.side();
};
```

Видео говорит, что `default`-методы добавлены «только для обратной совместимости». Это главная причина, но сегодня их также используют для удобных методов-комбинаторов (`Comparator.reversed()`, `Predicate.and()`), не злоупотребляя ими для хранения логики.
:::
