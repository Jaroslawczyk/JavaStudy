## Хеш-таблица

```text
индекс:  0      1      2      3      4                    …   15
       [null] [null] [null] [null] [Entry 20]→[Entry 36]  …  [null]
                                      (20 % 16 = 4, 36 % 16 = 4 — коллизия)
```

1. Внутри — массив «корзин» (bucket) из объектов `Entry { value, next }`, изначально на **16** ячеек.
2. Позиция элемента = `hashCode() % длина массива`.
3. Если корзина пуста — кладём туда. Если занята — сравниваем по **`equals`**: равны — это дубликат, не добавляем; не равны — **коллизия**, идём по цепочке `next` и добавляем в конец.
4. Когда элементов становится больше, чем `длина × 0,75` (**load factor**), массив **удваивается** и все элементы **перераспределяются** — ведь `hashCode % 32` уже не то же самое, что `% 16`.

Порядок элементов определяется хеш-кодами, а не порядком добавления, — отсюда «хаотичный» вывод и отсутствие доступа по индексу.

## Реализация CarHashSet (сокращённо)

```java
public class CarHashSet implements CarSet {
    private static final int INITIAL_CAPACITY = 16;
    private static final double LOAD_FACTOR = 0.75;
    private Entry[] array = new Entry[INITIAL_CAPACITY];
    private int size = 0;

    private static class Entry {
        private final Car value;
        private Entry next;
        Entry(Car value, Entry next) { this.value = value; this.next = next; }
    }

    @Override
    public boolean add(Car car) {
        if (size >= array.length * LOAD_FACTOR) {
            increaseArray();
        }
        boolean added = add(car, array);
        if (added) size++;
        return added;
    }

    private boolean add(Car car, Entry[] dst) {
        int position = getElementPosition(car, dst.length);
        if (dst[position] == null) {
            dst[position] = new Entry(car, null);
            return true;
        }
        Entry existed = dst[position];
        while (true) {
            if (existed.value.equals(car)) return false;        // дубликат
            if (existed.next == null) {
                existed.next = new Entry(car, null);             // в конец цепочки
                return true;
            }
            existed = existed.next;
        }
    }

    private int getElementPosition(Car car, int arrayLength) {
        return Math.abs(car.hashCode() % arrayLength);
    }

    private void increaseArray() {
        Entry[] newArray = new Entry[array.length * 2];
        for (Entry entry : array) {
            for (Entry e = entry; e != null; e = e.next) {
                add(e.value, newArray);                          // пересчёт позиций
            }
        }
        array = newArray;
    }

    // remove, contains, size, clear — см. видео
}
```

:::warning "Классы-элементы обязаны правильно реализовать equals и hashCode"
Хеш-коллекция находит корзину по `hashCode()`, а сравнивает элементы по `equals()`. Если у `Car` переопределён только `equals`, два одинаковых автомобиля попадут в разные корзины — и в множестве окажутся дубликаты (вопрос 3 ниже).
:::

## Сложность HashSet

| Операция | Средний случай | Худший случай |
|---|---|---|
| `add`, `remove`, `contains` | **O(1)** | O(n) при всех элементах в одной корзине (в реальном JDK — O(log n), см. урок о `HashMap`) |

## Вопросы с собеседований

:::interview "Из видео"
1. **Почему в Set нет `get(index)`, `remove(index)`, `add(e, index)`?** — Позиция элемента определяется хеш-кодом, а не порядком; понятия «индекс» нет.
2. **Гарантируется ли порядок элементов в HashSet?** — Нет: элементы раскладываются по хеш-кодам, а при расширении таблицы ещё и перераспределяются.
3. **Что будет, если переопределить `equals`, но не `hashCode`?** — Одинаковые объекты получат разные хеш-коды и разные корзины: дубликаты будут добавляться, `contains`/`remove` станут работать непредсказуемо.
4. **Что будет, если `hashCode` всегда возвращает 1?** — Все элементы попадут в одну корзину, она выродится в список: операции станут O(n).
5. **Почему для Set сделали отдельный интерфейс, а не реализовали List?** — Set не может реализовать индексные методы `List`; общие методы вынесены в родительский `Collection`.
:::

## Что не рассказано в видео

### Ловушка Math.abs

В видео модуль берётся **после** деления — `Math.abs(hash % n)`, и это безопасно. Но частый вариант «наоборот» — `Math.abs(hash) % n` — ломается: `Math.abs(Integer.MIN_VALUE)` возвращает **отрицательное** `-2147483648` (урок о перегрузке), и при длине массива, не равной степени двойки, индекс станет отрицательным. Самый понятный способ — `Math.floorMod(hash, n)`: результат всегда в диапазоне `[0, n)`.

### Как это сделано в JDK

- Ёмкость таблицы всегда **степень двойки**, а индекс считается побитово: `(n - 1) & (h ^ (h >>> 16))` — быстрее деления и лучше «перемешивает» плохие хеш-коды.
- Настоящий `HashSet` вообще не содержит своей хеш-таблицы: внутри него лежит **`HashMap`**, где элементы — ключи (разберём в уроке о `HashMap`).
- `HashSet` допускает один `null`.
- Если порядок важен — `LinkedHashSet` (порядок добавления) или `TreeSet` (сортировка).
