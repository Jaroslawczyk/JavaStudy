## Проблема массивов

Чтобы «добавить» элемент в массив, нужно создать новый массив на 1 больше и скопировать туда всё. Чтобы «удалить» — новый массив на 1 меньше и копирование без удалённого элемента. Каждый раз вручную, с риском ошибиться в индексах. Коллекция прячет эту работу внутри.

## Собственная коллекция

```java
public class MyArrayList {
    private String[] array = new String[10];   // внутреннее хранилище
    private int size;                          // сколько элементов реально лежит

    public void add(String s) {
        array[size] = s;
        size++;
        if (size == array.length) {            // места нет — увеличиваем в 2 раза
            String[] newArray = new String[array.length * 2];
            for (int i = 0; i < array.length; i++) {
                newArray[i] = array[i];
            }
            array = newArray;
        }
    }

    public void remove(int index) {
        if (index >= 0 && index < size) {
            for (int i = index; i < size - 1; i++) {
                array[i] = array[i + 1];       // сдвигаем хвост влево
            }
            size--;
        }
    }

    public void remove(String s) {
        int index = -1;
        for (int i = 0; i < size; i++) {
            if (s.equals(array[i])) {
                index = i;
                break;
            }
        }
        if (index != -1) {
            remove(index);
        }
    }

    public String get(int index) {
        if (index >= 0 && index < size) {
            return array[index];
        }
        return "Элемент не найден";
    }

    public int getSize() {
        return size;
    }
}
```

```text
size = 4, удаляем index = 1:
[ Никита | Игорь | Ваня | Алексей | … ]
          ◄──── сдвиг ────
[ Никита | Ваня | Алексей | Алексей | … ]   size = 3 → последний «лишний» элемент игнорируется
```

Ключевая идея: **ёмкость** (`array.length`) и **размер** (`size`) — разные вещи. Массив всегда чуть больше, чем нужно, поэтому `add` обычно работает мгновенно, а дорогое копирование происходит редко.

## Что не рассказано в видео

### Сложность операций (Big O)

| Операция | Сложность | Почему |
|---|---|---|
| `get(index)` | O(1) | Прямой доступ по индексу массива |
| `add(element)` в конец | O(1) амортизированно | Обычно просто запись; изредка — копирование O(n) |
| `remove(index)` | O(n) | Сдвиг всех элементов правее |
| `remove(String)` / поиск | O(n) | Перебор по порядку |

Этот вопрос — классика собеседований («чем `ArrayList` отличается от `LinkedList`»), он подробно разобран во второй части курса.

### Как это сделано в настоящем ArrayList

- Начальная ёмкость — 10 (выделяется при первом добавлении), рост — **в 1,5 раза** (`oldCapacity + (oldCapacity >> 1)`), а не в 2.
- Копирование — не циклом, а быстрым нативным `System.arraycopy` / `Arrays.copyOf`.
- `get` с неверным индексом **бросает** `IndexOutOfBoundsException`, а не возвращает строку-заглушку. Возвращать «Элемент не найден» опасно: вызывающий код не отличит заглушку от реальной строки.

### Утечка памяти при удалении

Автор говорит, что после сдвига последнему элементу не нужно присваивать `null`. Для корректности *поведения* это так, но для **памяти** — нет: массив продолжает держать ссылку на объект, и сборщик мусора не может его удалить («loitering»). Настоящий `ArrayList` делает `elementData[--size] = null;`.

### Почему нельзя перебрать в for-each

for-each работает с массивами и с объектами, реализующими интерфейс `Iterable`. Чтобы `for (String s : myList)` заработал, `MyArrayList` должна реализовать `Iterable<String>` — интерфейсы будут в следующих уроках, а свою реализацию итератора вы напишете во второй части курса.

### Обобщения (generics)

`MyArrayList` хранит только `String`. Чтобы одна коллекция подходила для любых типов — `MyArrayList<T>` — нужны дженерики (часть 2 курса).

:::task easy "Написать заново"
Не подглядывая, заново напишите `MyArrayList` с методами `add`, `remove(int)`, `remove(String)`, `get`, `getSize`. Проверьте: добавьте 25 элементов (массив должен расшириться дважды), удалите первый, последний и средний.
:::

:::task easy "contains и indexOf"
Добавьте методы `boolean contains(String s)` и `int indexOf(String s)` (возвращает −1, если не найдено). Перепишите `remove(String)` через `indexOf`.
:::

:::task medium "add по индексу и set"
Добавьте `add(int index, String s)` — вставку со сдвигом элементов вправо — и `set(int index, String s)` — замену. Не забудьте расширение массива при вставке.
??? Подсказка
Сначала убедитесь, что есть место (если `size == array.length` — расширьте), затем сдвигайте с конца: `for (int i = size; i > index; i--) array[i] = array[i - 1];`.
:::

:::task medium "Правильные ошибки и память"
Измените `get` и `remove(int)` так, чтобы при неверном индексе они бросали `IndexOutOfBoundsException` с сообщением вида `Index: 12, Size: 5`. В `remove` обнуляйте освободившуюся ячейку. Добавьте `toString()`, возвращающий `[a, b, c]`.
:::

:::task hard "MyIntList и сравнение скорости"
Создайте аналогичную коллекцию для `int` (`MyIntList`). Добавьте в неё 10 млн чисел и замерьте время (`System.nanoTime()`) для роста в 2 раза и в 1,5 раза, а также сравните с `ArrayList<Integer>`. Почему `ArrayList<Integer>` занимает в памяти заметно больше?
??? Подсказка
`ArrayList<Integer>` хранит не числа, а ссылки на объекты `Integer` (автоупаковка — следующий урок): каждое число — отдельный объект с заголовком. `int[]` хранит значения подряд.
:::
