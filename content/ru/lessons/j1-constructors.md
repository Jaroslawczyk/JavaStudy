**Конструктор** — специальный метод, который вызывается при создании объекта через `new`. Он позволяет сразу задать начальные значения полей и не забыть ни одно из них.

## Синтаксис

```java
public class Box {
    double width;
    double height;
    double length;

    Box(double width, double height, double length) {   // имя = имя класса, нет типа возврата
        this.width = width;
        this.height = height;
        this.length = length;
    }

    double volume() {
        return width * height * length;
    }
}
```

```java
Box box = new Box(10, 15, 20);   // конструктор вызывается автоматически
System.out.println(box.volume()); // 3000.0
```

Отличия конструктора от метода:

- имя **точно совпадает** с именем класса;
- **нет типа возвращаемого значения** — даже `void` (если написать `void Box()`, это будет обычный метод, а не конструктор!);
- вызывается только через `new` (или из другого конструктора через `this(...)`/`super(...)`).

## Конструктор по умолчанию

Если вы **не написали ни одного** конструктора, компилятор добавляет пустой конструктор без параметров — поэтому `new Box()` работал раньше. Поля при этом получают значения по умолчанию (`0`, `false`, `null`).

:::warning "Конструктор по умолчанию исчезает"
Как только вы объявили **любой** свой конструктор (например, с параметрами), Java конструктор по умолчанию **не создаёт**. `new Box()` перестанет компилироваться — нужно либо передавать аргументы, либо самому объявить конструктор без параметров.
:::

## Генерация в IntelliJ IDEA

<kbd>Alt+Insert</kbd> (macOS: <kbd>⌘N</kbd>) → **Constructor** → выберите поля (с <kbd>Ctrl</kbd> или <kbd>Shift</kbd>) → OK. Так же генерируются getter/setter, `equals()`, `hashCode()`, `toString()`.

## Что не рассказано в видео

### Вызов одного конструктора из другого: this(...)

Чтобы не дублировать код в нескольких конструкторах (их перегрузку разберём в следующем уроке), один конструктор вызывает другой:

```java
Box(double size) {
    this(size, size, size);   // должен быть первой инструкцией*
}
```

\* До Java 25 вызов `this(...)`/`super(...)` обязан был быть **первой** строкой. С Java 25 (JEP 513, «гибкие тела конструкторов») до него можно проверять аргументы и даже присваивать поля, но нельзя читать поля и вызывать методы создаваемого объекта.

### Проверка аргументов

Конструктор — лучшее место, чтобы не допустить создания «неправильного» объекта:

```java
Box(double width, double height, double length) {
    if (width <= 0 || height <= 0 || length <= 0) {
        throw new IllegalArgumentException("Размеры должны быть положительными");
    }
    this.width = width;
    this.height = height;
    this.length = length;
}
```

Исключения подробно разобраны в уроке об исключениях.

### Неизменяемые объекты

Если поля помечены `final`, их нужно присвоить ровно один раз — в конструкторе. Такой объект нельзя изменить после создания (immutable), что делает код безопаснее, особенно в многопоточности:

```java
public class Point {
    private final double x;
    private final double y;

    public Point(double x, double y) {
        this.x = x;
        this.y = y;
    }
}
```

### Порядок инициализации объекта

1. Память под объект, поля = значения по умолчанию.
2. Инициализаторы полей (`double width = 10;`) и блоки инициализации `{ … }` — в порядке записи.
3. Тело конструктора.

Подробнее — в статье [Блоки инициализации](#/extra/initializer-blocks).

### Конструкторы в реальных проектах

- **Lombok**: аннотации `@NoArgsConstructor`, `@AllArgsConstructor`, `@RequiredArgsConstructor` генерируют конструкторы при компиляции.
- **record** (Java 16+) создаёт конструктор со всеми полями автоматически.
- В Spring зависимости внедряются **через конструктор** (constructor injection) — это рекомендуемый способ.

??? Подсказка
НОД по алгоритму Евклида: `while (b != 0) { int t = a % b; a = b; b = t; } return Math.abs(a);`. Сумма: `a/b + c/d = (a*d + c*b) / (b*d)` — затем конструктор сам сократит результат.
