**Перегрузка (overloading)** — несколько методов или конструкторов с одинаковым именем, но разными параметрами. Здесь же — первое знакомство с `static` и вызов одного метода из другого.

## Перегрузка методов

```java
public class Calc {
    static int multiple(int a, int b) {
        return a * b;
    }

    static double multiple(double a, double b) {
        return a * b;
    }

    static int multiple(int a) {
        return a * a;
    }
}
```

```java
Calc.multiple(6, 5);       // 30   → multiple(int, int)
Calc.multiple(6.3, 5.8);   // 36.54 → multiple(double, double)
Calc.multiple(5);          // 25   → multiple(int)
```

Компилятор выбирает версию по **количеству и типам аргументов**. Так устроены многие методы JDK: `Math.abs` существует в четырёх вариантах — для `int`, `long`, `float`, `double`; `System.out.println` — для всех типов.

### Правила

- Перегруженные методы должны отличаться **количеством** параметров, их **типами** или **порядком типов**.
- **Только типа возвращаемого значения недостаточно**: `int f(int a)` и `double f(int a)` — ошибка компиляции.
- Имена параметров роли не играют.

:::tip "Принцип наименьшего удивления"
Перегружайте только методы, которые делают **одно и то же** для разных входных данных. `multiple(int, int)`, который умножает, и `multiple(double, double)`, который вычитает, формально скомпилируются, но запутают всех, кто будет пользоваться вашим кодом.
:::

## Первое знакомство со static

Методы `multiple` не используют полей объекта — им нужны только параметры. Создавать объект ради них бессмысленно, поэтому их объявляют `static` и вызывают через имя класса: `Calc.multiple(5)`. Ровно так вы уже вызывали `Math.sqrt(36)`.

Подробно о `static` — в уроке о статических членах класса.

## Перегрузка конструкторов

```java
public class Box {
    double width, height, length;

    Box(double width, double height, double length) {
        this.width = width;
        this.height = height;
        this.length = length;
    }

    Box(double size) {           // куб
        this(size, size, size);  // лучше вызвать другой конструктор, чем копировать код
    }

    Box() {                      // пустая коробка
        this(0);
    }

    double volume() {
        return width * height * length;
    }

    void showVolume() {
        System.out.println("Объём: " + volume());   // вызов метода из метода
    }
}
```

```java
new Box(10).showVolume();          // 1000.0
new Box(15, 20, 25).showVolume();  // 7500.0
new Box().showVolume();            // 0.0
```

:::note "Про public"
Автор в видео замечает, что иногда «по привычке» пишет `public` перед конструктором и обещает объяснить это позже — модификаторы доступа разобраны через урок.
:::

## Что не рассказано в видео

### Как компилятор выбирает перегрузку

Если точного совпадения нет, компилятор пробует **расширяющее приведение** аргументов:

```java
Calc.multiple(5, 2.0);   // int 5 расширяется до double → multiple(double, double) = 10.0
```

Порядок поиска: точное совпадение → расширение примитивов → автоупаковка (`int` → `Integer`) → varargs. Если подходят два варианта одинаково — ошибка «ambiguous method call».

### Перегрузка ≠ переопределение

| | Перегрузка (overloading) | Переопределение (overriding) |
|---|---|---|
| Где | В одном классе (или в наследнике) | В классе-наследнике |
| Сигнатура | Разные параметры | Та же сигнатура |
| Когда выбирается | При компиляции (статическое связывание) | Во время выполнения (динамическое связывание) |

Переопределение — в уроке о наследовании; про связывание — в статье [Static vs Dynamic Binding](#/extra/binding).

### Ловушка Math.abs

```java
Math.abs(Integer.MIN_VALUE);   // -2147483648 — модуль не помещается в int!
```

Классический пример переполнения, иногда встречается на собеседованиях.

Создайте класс `Monster` с полями: количество глаз, ног и рук. Конструктор без параметров ставит всем полям значение 2 («обычный монстр похож на человека»). Ещё три конструктора: с количеством глаз; с глазами и руками; со всеми тремя параметрами (недостающие значения = 2). Метод `voice()` выводит «Голос»; перегрузка `voice(int n)` выводит «Голос» n раз; перегрузка `voice(int n, String word)` выводит переданное слово n раз. {{t j1 2:39:22}}
??? Подсказка
Пусть каждый «короткий» конструктор вызывает самый полный через `this(...)`: `Monster(int eyes) { this(eyes, 2, 2); }`. Так же `voice()` может вызывать `voice(1)`, а `voice(int n)` — `voice(n, "Голос")`.
:::

:::task hard "Какую перегрузку вызовут?"
Объявите методы `print(int x)`, `print(long x)`, `print(Integer x)`, `print(Object x)`, `print(int... x)`, каждый выводит своё название. Вызовите `print(5)`, `print(5L)`, `print((short) 5)`, `print(Integer.valueOf(5))`, `print("5")`, `print()`. Сначала **предскажите** результат, затем проверьте и объясните порядок выбора.
??? Подсказка
Порядок: точное совпадение → расширение примитива (`short` → `int`) → упаковка → varargs. `print("5")` попадёт в `Object`, `print()` — только в varargs.
:::
