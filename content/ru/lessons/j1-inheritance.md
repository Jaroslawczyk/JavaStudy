## Синтаксис

```java
public class CatFamily {
    private int ears;
    private int paws;
    private boolean bigClaws;

    public CatFamily(int ears, int paws, boolean bigClaws) {
        this.ears = ears;
        this.paws = paws;
        this.bigClaws = bigClaws;
    }

    public void eat() {
        System.out.print("Кушаю ");
    }

    public void showInfo() {
        System.out.println("Уши: " + ears + ", лапы: " + paws + ", большие когти: " + bigClaws);
    }
}
```

```java
public class Cat extends CatFamily {           // Cat — подкласс, CatFamily — суперкласс
    public Cat() {
        super(2, 4, false);                     // сначала создаётся «родительская часть»
    }

    @Override
    public void eat() {
        super.eat();                            // вызвать версию суперкласса
        System.out.println("вискас");
    }
}

public class Leon extends CatFamily {
    public Leon() {
        super(2, 4, true);
    }

    @Override
    public void eat() {
        super.eat();
        System.out.println("антилопу");
    }
}
```

```java
new Cat().eat();        // Кушаю вискас
new Leon().eat();       // Кушаю антилопу
new Leon().showInfo();  // метод унаследован, данные — льва
```

## Главные правила

- **Подкласс наследует** все поля и методы, но `private`-члены ему **недоступны напрямую** — работайте через `public`/`protected`-методы или конструктор суперкласса.
- **Конструктор подкласса всегда сначала вызывает конструктор суперкласса.** Если вы не написали `super(...)`, компилятор вставит `super()` — вызов конструктора **без параметров**. Если у родителя такого нет — ошибка компиляции (именно это случилось с `Leon` в видео).
- В Java класс может наследоваться **только от одного** класса.

## Переопределение и @Override

**Переопределение (override)** — подкласс даёт свою реализацию метода с **той же сигнатурой**, что у родителя.

`@Override` ничего не меняет в работе программы, но:

1. показывает читателю, что метод переопределяет родительский;
2. заставляет компилятор проверить это: опечатка (`eatt()`) сразу станет ошибкой, а не тихо создаст новый метод.

:::tip
Всегда ставьте `@Override`. <kbd>Ctrl+O</kbd> (Override Methods) в IDEA делает это автоматически.
:::

## Что не рассказано в видео

### Object — предок всех классов

Если `extends` не указан, класс неявно наследуется от `java.lang.Object`. Поэтому у любого объекта есть методы `toString()`, `equals()`, `hashCode()`, `getClass()`. Их часто переопределяют:

```java
@Override
public String toString() {
    return "Cat{ears=2, paws=4}";
}
// System.out.println(cat) теперь печатает понятный текст, а не Cat@1b6d3586
```

### Модификатор protected

`protected`-члены доступны в подклассах (даже в других пакетах) и внутри своего пакета. Компромисс между `private` и `public`, когда наследнику действительно нужен прямой доступ.

### Правила переопределения

- Нельзя **сужать** доступ: `public` метод нельзя переопределить как `protected`.
- Тип возврата — тот же или **подтип** (ковариантный возврат).
- Нельзя бросать новые **проверяемые** исключения, которых нет у родителя.
- `static` и `private` методы не переопределяются (статические — «скрываются»).
- `final` метод переопределить нельзя (следующий урок).

### Порядок создания объекта подкласса

`new Cat()` → конструктор `Cat` → сначала `super(...)` → конструктор `CatFamily` → (выше — `Object`) → затем остальное тело конструктора `Cat`. Родитель всегда «собирается» первым.

### Наследование vs композиция

Наследование выражает отношение **«является» (is-a)**: кот *является* кошачьим. Если отношение **«имеет» (has-a)** — машина *имеет* двигатель — используйте **композицию** (поле типа `Engine`), а не наследование. Принцип «предпочитайте композицию наследованию» — из книги «Effective Java», его часто вспоминают на собеседованиях.

:::outdated "Ограниченное наследование: sealed (Java 17+)"
С Java 17 можно явно перечислить, кто имеет право наследоваться от класса:

```java
public sealed class Shape permits Circle, Square { }
public final class Circle extends Shape { }
public final class Square extends Shape { }
```

Это помогает моделировать закрытые иерархии и отлично сочетается с pattern matching в `switch`.
:::
