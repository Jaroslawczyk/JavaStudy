Начинаем вторую часть курса с **дженериков** (generics, обобщённые типы). Это механизм, благодаря которому `List<String>` хранит только строки, а компилятор ловит ошибки типов ещё до запуска программы. Без дженериков невозможно читать ни один современный Java-код: коллекции, Stream API, Optional, Spring — всё построено на них.

## Проблема: контейнер для Object

Допустим, нужна «коробка», которая хранит что угодно. До Java 5 писали так:

```java
public class Box {
    private Object item;

    public Box(Object item) { this.item = item; }
    public Object getItem() { return item; }
}

Box box1 = new Box(5);
Box box2 = new Box("10");           // ошибка, но компилятор молчит
int sum = (Integer) box1.getItem() + (Integer) box2.getItem();
// ClassCastException: String cannot be cast to Integer — во время выполнения!
```

Две беды: **ручные приведения типов** на каждом шагу и **ошибки, которые всплывают только при запуске**.

## Решение: параметр типа

```java
public class Box<T> {          // T — параметр типа (Type)
    private T item;

    public Box(T item) { this.item = item; }
    public T getItem() { return item; }
}

Box<Integer> box1 = new Box<>(5);
Box<Integer> box2 = new Box<>("10");   // ❌ ошибка компиляции — то, что нужно
int sum = box1.getItem() + box2.getItem();  // без приведений
```

- `T` — просто имя-заполнитель. По соглашению: `T` (type), `E` (element), `K`/`V` (key/value), `R` (result), `U`, `S` — дополнительные типы.
- `<>` справа — **diamond operator** (Java 7+): тип выводится из левой части.
- Параметров может быть несколько: `class Box<K, V>`, как `Map<K, V>`.

```java
public class Pair<K, V> {
    private final K key;
    private final V value;
    public Pair(K key, V value) { this.key = key; this.value = value; }
    public K getKey() { return key; }
    public V getValue() { return value; }
}

Pair<String, Integer> age = new Pair<>("Анна", 30);
```

## Стирание типов (type erasure)

Дженерики существуют **только для компилятора**. После компиляции `Box<Integer>` и `Box<String>` — это один и тот же класс `Box`, а `T` заменяется на `Object` (или на границу, если она есть — см. урок [Ограничения и wildcard](#/lessons/j2-bounded-wildcards)). Компилятор сам вставляет приведения типов в нужных местах.

Отсюда следствия, о которых спрашивают на собеседованиях:

| Нельзя | Почему |
|---|---|
| `new T()` | В рантайме неизвестно, что такое `T` |
| `new T[10]` | То же; массивы «знают» свой тип в рантайме |
| `obj instanceof Box<String>` | Информации о `String` нет (можно `instanceof Box<?>`) |
| `Box<int>` | Параметр — только ссылочный тип; используйте `Integer` (автоупаковка) |
| Перегрузить `m(List<String>)` и `m(List<Integer>)` | После стирания сигнатуры одинаковы |
| Статическое поле типа `T` | Статика общая для всех `Box<…>`, а `T` у каждого свой |

:::interview "Вопрос с собеседования"
**Что такое type erasure?** — Компилятор проверяет типы по дженерикам, а затем стирает параметры типов: в байткоде остаются «сырые» типы (`Object` или верхняя граница), а приведения вставляются автоматически. Поэтому в рантайме `List<String>` и `List<Integer>` неотличимы. Сделано ради обратной совместимости с кодом до Java 5.
:::

## Что не рассказано в видео

### Raw types — «сырые» типы

`Box box = new Box(5);` без угловых скобок — **raw type**. Он оставлен ради совместимости, компилятор выдаёт предупреждение `unchecked`. В новом коде raw types не используйте: вы теряете всю проверку типов.

### `var` и дженерики (Java 10+)

```java
var map = new HashMap<String, List<Integer>>();   // тип выводится справа
```

С `var` нельзя писать пустой diamond `<>` справа — компилятору не из чего вывести тип (получится `HashMap<Object, Object>`).

### Records тоже бывают обобщёнными

```java
record Pair<K, V>(K key, V value) {}          // Java 16+
var p = new Pair<>("Java", 25);
```

Подробнее о записях — в статье [Records](#/extra/records).

:::outdated "Как сейчас создают небольшие коллекции"
В видео коллекции создаются через `new ArrayList<>()` и `add`. Для небольших неизменяемых наборов с Java 9 есть фабрики: `List.of(1, 2, 3)`, `Set.of("a", "b")`, `Map.of("k", 1)`. Они короче и безопаснее (попытка изменить бросит `UnsupportedOperationException`).
:::

:::note "Будущее: дженерики над примитивами"
Сейчас `List<int>` невозможен, и `List<Integer>` хранит упакованные объекты — это лишняя память и работа для сборщика мусора. Проект **Valhalla** (value classes) давно готовит исправление; на 2026 год это ещё не часть стабильной Java. Для больших наборов чисел используйте `int[]` или `IntStream`.
:::
