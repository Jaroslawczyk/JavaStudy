## Процессы и потоки

- **Процесс** — запущенная программа со своей памятью (браузер, IDE, плеер). ОС выполняет процессы параллельно — это **многозадачность на основе процессов**.
- **Поток (thread)** — «линия выполнения» внутри процесса. Потоки одного процесса **делят общую память** (кучу), но у каждого свой стек. Это **многопоточность на основе потоков**: в одной программе одновременно идёт загрузка, рисуется прогресс-бар и считается оставшееся время.

Когда JVM запускает программу, создаётся **главный поток**, который выполняет `main`. Пока вы не создадите другие потоки, всё выполняется последовательно.

## Способ 1: наследование от Thread

```java
public class MyThread extends Thread {
    @Override
    public void run() {                  // что делать в новом потоке
        for (int i = 0; i < 1000; i++) {
            System.out.print(i + " ");
        }
    }
}

public static void main(String[] args) {
    System.out.println("Start");
    new MyThread().start();              // запускаем НОВЫЙ поток
    for (int i = 0; i < 1000; i++) System.out.print("M");
    System.out.println("\nFinish");
}
```

Вывод каждый раз разный: `Start`, буквы `M`, числа и `Finish` перемешиваются. Создание потока занимает время, поэтому главный поток часто успевает напечатать `Finish` раньше, чем новый — первое число.

## Способ 2: реализация Runnable

```java
public class MyRunnable implements Runnable {
    @Override
    public void run() {
        for (int i = 0; i < 1000; i++) System.out.print(i + " ");
    }
}

new Thread(new MyRunnable()).start();

// или анонимным классом / лямбдой:
new Thread(() -> System.out.println("Работаю в " + Thread.currentThread().getName())).start();
```

**`Runnable` предпочтительнее:** в Java нет множественного наследования классов — унаследовавшись от `Thread`, вы теряете возможность наследоваться от чего-то ещё. Кроме того, `Runnable` отделяет **задачу** («что делать») от **механизма выполнения** («кто и как»): ту же задачу можно отдать пулу потоков или виртуальному потоку.

## start() и run()

```java
Thread t = new Thread(task);
t.run();     // ❌ просто вызов метода в ТЕКУЩЕМ потоке — никакой многопоточности
t.start();   // ✅ JVM создаёт новый поток и в нём вызывает run()
```

`run()` — это всего лишь метод, который вы сами переопределили: в нём нет никакого кода создания потоков. Поток создаёт `start()` — нативный метод класса `Thread`. `run()` вручную не вызывают никогда.

:::interview "Вопросы с собеседования"
**Какие способы создания потока вы знаете?** — Унаследоваться от `Thread` и переопределить `run()` или реализовать `Runnable` и передать его в конструктор `Thread`. Предпочтительнее `Runnable`. Современный ответ стоит дополнить: `Callable` + `ExecutorService` и виртуальные потоки (Java 21).

**Чем отличаются `start()` и `run()`?** — `start()` создаёт новый поток и вызывает в нём `run()` (асинхронно). Прямой вызов `run()` выполнит код в текущем потоке. Повторный `start()` того же объекта бросит `IllegalThreadStateException`.
:::

## Что не рассказано в видео

### Имена и информация о потоке

```java
Thread t = new Thread(task, "downloader");      // имя пригодится в логах
Thread current = Thread.currentThread();
System.out.println(current.getName() + " id=" + current.threadId());
```

:::outdated "getId() → threadId()"
`Thread.getId()` устарел с Java 19 — используйте `threadId()`. Также с Java 19 есть `Thread.sleep(Duration)`.
:::

### Конкурентность и параллелизм

- **Параллелизм** — задачи буквально выполняются одновременно на разных ядрах.
- **Конкурентность** — задачи чередуются, создавая иллюзию одновременности (даже на одном ядре).

Многопоточная программа на 8 ядрах может быть и тем, и другим. Число ядер: `Runtime.getRuntime().availableProcessors()`.

### Виртуальные потоки (Java 21+)

Обычный (платформенный) поток Java = поток ОС: он тяжёлый (стек ~1 МБ), тысячи таких потоков — уже проблема. **Виртуальные потоки** — лёгкие потоки, которыми управляет JVM; их можно создавать миллионами для задач, которые много ждут (сеть, БД, файлы):

```java
Thread.ofVirtual().start(() -> System.out.println("Я виртуальный"));
Thread.ofPlatform().name("worker").start(task);    // builder и для обычных
```

Подробно — в статье [Virtual Threads](#/extra/virtual-threads).
