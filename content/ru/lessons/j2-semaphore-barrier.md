## Semaphore

Семафор хранит число «разрешений». `acquire()` берёт разрешение (или ждёт, если их нет), `release()` возвращает.

```java
private static final Semaphore semaphore = new Semaphore(3);   // не более 3 потоков

static void workWithFileSystem() {
    String name = Thread.currentThread().getName();
    try {
        semaphore.acquire();                   // −1 или ждать
        try {
            System.out.println(name + " работает с файловой системой");
            Thread.sleep(1000);
        } finally {
            semaphore.release();               // +1, даже если упали
        }
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
}
```

Все 10 потоков параллельно делают «свою» работу, но в критический участок одновременно попадают максимум три. Пул из 3 потоков так не умеет: он ограничил бы **всю** работу ({{t j2 3:36:36}}).

:::warning "release — строго в finally и строго после успешного acquire"
Если `acquire()` прервали, разрешение не было получено — и `release()` вызывать нельзя, иначе разрешений станет больше, чем было. Поэтому `release` во **внутреннем** `try` после `acquire`, а не во внешнем.
:::

Где применяют: ограничение одновременных запросов к внешнему API, пул соединений, rate limiting. `new Semaphore(n, true)` — «честный» режим (FIFO).

## CyclicBarrier

Барьер на N участников: каждый, дойдя до точки, вызывает `await()` и ждёт; когда собрались все N — барьер открывается, и все продолжают одновременно. Затем барьер **автоматически взводится снова**.

```java
CyclicBarrier barrier = new CyclicBarrier(2, () -> System.out.println("Пара готова!"));

executor.execute(() -> {
    prepareData();
    try {
        barrier.await();                  // ждём ещё одного
    } catch (InterruptedException | BrokenBarrierException e) {
        throw new RuntimeException(e);
    }
    System.out.println(Thread.currentThread().getName() + " продолжает");
});
```

Второй аргумент конструктора — действие, выполняемое при каждом открытии барьера. Если один из ждущих прерван, барьер «ломается» и остальные получают `BrokenBarrierException`.

| | `CountDownLatch` | `CyclicBarrier` | `Semaphore` |
|---|---|---|---|
| Идея | ждать N событий | N потоков ждут друг друга | не более N потоков внутри |
| Кто ждёт | любые потоки через `await()` | сами участники | желающие войти |
| Повторное использование | ❌ одноразовый | ✅ сбрасывается | ✅ |

:::note "Phaser и Exchanger"
В видео упоминаются «ещё несколько классов». **`Phaser`** (Java 7) — гибкий барьер с переменным числом участников и множеством фаз. **`Exchanger`** — точка обмена данными между двумя потоками.
:::

## Разбор гонки (кратко)

- 10 машин = 10 задач в `ExecutorService`.
- Старт одновременно после подготовки → `CyclicBarrier(10)` (или `CountDownLatch`).
- В тоннеле не больше 3 машин → `Semaphore(3)` вокруг этапа «тоннель».
- Результаты → `ConcurrentHashMap<Integer, Long>`.
- Ждём финиша всех → `CountDownLatch(10)`.
- Победитель — первый финишировавший: `synchronized`-блок (или `AtomicInteger.compareAndSet(-1, index)`) вокруг «если победителя ещё нет — это я».
