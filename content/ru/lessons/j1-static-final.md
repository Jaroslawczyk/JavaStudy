## static — принадлежит классу

| | Нестатический (экземпляра) | Статический (`static`) |
|---|---|---|
| Принадлежит | Конкретному объекту | Классу целиком — один на всех |
| Вызов | `box.volume()` | `MyMath.square(20)` |
| Нужен объект? | Да | Нет |
| Доступ к полям экземпляра | Да | **Нет** — объекта может не существовать |

```java
public class MyMath {
    private static final double PI = 3.14;

    public static int square(int number) {
        return number * number;
    }

    public static double length(double radius) {
        return 2 * PI * radius;
    }

    public static double area(double radius) {
        return PI * radius * radius;
    }
}
```

```java
System.out.println(MyMath.square(20));    // 400
System.out.println(MyMath.length(10));    // 62.8
```

:::warning "Статический метод не видит поля экземпляра"
Если `pi` объявить обычным полем (`private double pi = 3.14;`), то `return 2 * pi * radius;` в статическом методе не скомпилируется: `non-static variable pi cannot be referenced from a static context`. Статический метод вызывается **без объекта**, а значит, полей конкретного объекта у него нет.
:::

## Опасность общего изменяемого состояния

Статическое поле — **одно на всю программу**. В видео «программист-двоечник» в своём методе `area` пишет `pi = 10;` — и после этого **ваш** метод `length` начинает возвращать неверные значения. Один метод незаметно сломал другой через общее поле.

## final — присвоить только один раз

```java
private static final double PI = 3.14;
PI = 10;   // ошибка компиляции: cannot assign a value to final variable PI
```

- **Константа** = `static final`. Имя — `UPPER_SNAKE_CASE`: `PI`, `MAX_SIZE`, `DEFAULT_TIMEOUT`.
- Константу не страшно сделать `public` — изменить её всё равно нельзя (так устроен `Math.PI`). Но если внешний доступ не нужен — `private`.

## Аргументы переменной длины (varargs)

```java
public static int sum(int... numbers) {   // внутри numbers — обычный int[]
    int sum = 0;
    for (int number : numbers) {
        sum += number;
    }
    return sum;
}
```

```java
MyMath.sum();              // 0
MyMath.sum(1);             // 1
MyMath.sum(1, 2, 3, 4);    // 10
MyMath.sum(new int[]{5, 5}); // 10 — можно передать и массив
```

Правила: varargs-параметр может быть только **один** и только **последним**: `format(String pattern, Object... args)`.

## public static void main(String[] args) — по словам

| Слово | Значение |
|---|---|
| `public` | Метод доступен отовсюду — JVM должна его вызвать |
| `static` | Объектов при старте программы ещё нет, поэтому точка входа не должна требовать объект |
| `void` | Метод ничего не возвращает |
| `main` | Имя, которое JVM ищет как точку входа |
| `String[] args` | Массив аргументов командной строки |

:::note "Про аргументы командной строки"
Автор говорит, что за всю карьеру ни разу не пользовался `args`. В веб-разработке это правда редкость, но в утилитах командной строки, скриптах, Docker-контейнерах и Spring Boot (`--server.port=9090`) аргументы используются постоянно.
:::

## Что не рассказано в видео

### Статическое поле — счётчик объектов

Классический пример полезного статического поля:

```java
public class User {
    private static int count = 0;   // общий для всех объектов
    private final int id;

    public User() {
        count++;
        id = count;
    }

    public static int getCount() {
        return count;
    }
}
```

### Все значения final

| Где | Что значит |
|---|---|
| `final` переменная/поле | Значение присваивается один раз |
| `final` параметр | Нельзя переприсвоить внутри метода |
| `final` метод | Нельзя **переопределить** в наследнике |
| `final` класс | Нельзя **наследовать** (например, `String`, `Integer`) |

Важно: `final` у ссылки запрещает менять **ссылку**, но не содержимое объекта: `final int[] arr = {1, 2}; arr[0] = 100;` — компилируется.

### Утилитные классы

Классы, состоящие только из статических методов (`Math`, `Arrays`, `Collections`), делают `final` и с `private`-конструктором, чтобы никто не создавал их объекты:

```java
public final class MyMath {
    private MyMath() { }   // объекты не нужны
    // только static-методы
}
```

### Статический импорт

```java
import static java.lang.Math.PI;
import static java.lang.Math.sqrt;

double r = sqrt(PI);   // без "Math."
```

Удобно в тестах (`assertEquals`), но злоупотреблять не стоит — непонятно, откуда метод.

### Почему статического состояния избегают

Изменяемые статические поля — фактически глобальные переменные: они усложняют тестирование и опасны в многопоточности. Константы (`static final`) и чистые статические функции — нормально; изменяемый `static` — только при веской причине.
