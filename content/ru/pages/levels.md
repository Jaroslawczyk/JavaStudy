# Уровни Java-разработчика: что знать и что доучить

Trainee, Junior, Middle (Regular), Senior, Lead — грейды отличаются не столько количеством выученных технологий, сколько **самостоятельностью и ответственностью**. Ниже — что обычно ожидают на каждом уровне в европейских и польских компаниях в 2026 году и что доучить после этого курса.

:::note "Ориентир, а не стандарт"
Требования сильно зависят от компании: Junior в банке и Junior в стартапе — разные роли. Смотрите на реальные вакансии на [justjoin.it и других площадках](#/page/career/jobs) и сравнивайте с этим списком.
:::

## Где вы после курса

Пройдя обе части курса и задачи, вы знаете **Java SE на уровне собеседования Junior**: ООП, коллекции и их устройство, дженерики, многопоточность, Stream API, ввод-вывод, исключения, JUnit. Этого достаточно для интервью по «ядру Java», но **недостаточно для работы**: нужны SQL, Spring Boot, Git, Docker и практический проект.

## Trainee / стажёр {#trainee}

**Кто это:** учится в процессе работы, задачи — под присмотром ментора.

- Java SE на уровне этого курса, базовый ООП и коллекции.
- Git: commit, branch, pull request.
- Основы SQL (`SELECT`, `JOIN`).
- Умение разобраться с задачей, задавать вопросы, гуглить и читать документацию.
- Английский — чтение документации (A2–B1).

**Где:** стажировки, академии и летние программы крупных компаний, банков и software house'ов.

## Junior {#junior}

**Кто это:** решает небольшие и средние задачи в существующем проекте; нужен ревью и периодическая помощь.

| Область | Ожидания |
|---|---|
| Java | Уверенно: ООП, коллекции, `equals/hashCode`, исключения, Stream API, основы многопоточности, Java 17–25 (records, `var`, switch-выражения) |
| Spring | Spring Boot, DI, REST-контроллеры, Spring Data JPA, валидация, конфигурация, профили |
| БД | SQL, связи, индексы на базовом уровне, транзакции, PostgreSQL |
| Тесты | JUnit, Mockito, понимание интеграционных тестов |
| Инструменты | Git, Maven/Gradle, IntelliJ IDEA, Docker (запустить приложение и БД), Postman/HTTP-клиент |
| Процессы | Scrum, Jira, code review |
| Английский | B1–B2: читать и писать техническую переписку |

**Портфолио:** 1–2 законченных проекта на GitHub — см. [проект для портфолио](#/page/career/portfolio).

## Middle / Regular {#middle}

**Кто это:** самостоятельно делает фичи от задачи до продакшена, ревьюит код Junior, понимает, *почему* система устроена именно так.

- Java глубже: JMM и [`volatile`](#/extra/jmm-volatile), `java.util.concurrent`, [виртуальные потоки](#/extra/virtual-threads), основы JVM и GC, профилирование.
- Spring глубже: транзакции и propagation, прокси, Spring Security, кеширование, обработка ошибок, тестирование слоёв.
- БД: оптимизация запросов (`EXPLAIN`), N+1, блокировки, миграции без простоя.
- Интеграции: Kafka/RabbitMQ, REST-клиенты, устойчивость (таймауты, ретраи, circuit breaker).
- Инфраструктура: Docker, Kubernetes на уровне пользователя, CI/CD, логи и метрики, облако (AWS/Azure).
- Архитектура: паттерны, SOLID, чистая/гексагональная архитектура, микросервисы и их компромиссы.
- Английский B2: участвовать в обсуждениях и демо.

## Senior {#senior}

**Кто это:** отвечает за технические решения в своей области, видит систему целиком, помогает расти команде.

- Проектирование систем: масштабирование, консистентность данных, распределённые транзакции (Saga, Outbox), выбор хранилищ.
- Производительность и надёжность: JVM-тюнинг, разбор инцидентов, observability, SLO.
- Безопасность и качество: threat modeling, стандарты кода, архитектурные тесты.
- Работа с людьми: менторинг, ревью архитектуры, оценки, общение с бизнесом.
- Умение выбирать **простое** решение и аргументированно говорить «нет».

## Lead / Architect / Staff {#lead}

Дальше путь расходится: **Tech Lead** (технические решения + координация команды), **Engineering Manager** (люди и процессы), **Architect / Staff / Principal Engineer** (архитектура на уровне нескольких команд или компании). Технологий здесь не больше — больше ответственности, влияния и коммуникации.

## Что доучить после этого курса {#after-course}

План на 4–6 месяцев при занятиях 10–15 часов в неделю:

1. **Повторить Java SE** по [Roadmap](#/roadmap) и дополнительным статьям: [records](#/extra/records), [enum](#/extra/enums), [java.time](#/extra/date-time), [функциональный стиль](#/extra/functional).
2. **SQL и PostgreSQL** — запросы, связи, индексы, транзакции (SQL-тренажёры, pgexercises).
3. **Git** — ежедневно, на своих проектах; pull request'ы.
4. **Maven/Gradle** — [статья](#/extra/build-tools).
5. **Spring Boot** — DI, REST, Data JPA, Security, тесты ([веб-фреймворки](#/extra/web-frameworks), [DI](#/extra/dependency-injection), [БД](#/extra/database-access)).
6. **Docker** и docker compose.
7. **Тестирование** — JUnit 6, Mockito, Testcontainers ([статья](#/extra/testing)).
8. **Проект для портфолио** с CI на GitHub Actions.
9. **Английский** — техническое чтение и разговорная практика.
10. **Подготовка к интервью** — повторите вопросы из уроков-собеседований и [итогового собеседования](#/lessons/j2-final-interview), решайте задачи на алгоритмы (LeetCode/HackerRank — уровня easy/medium).

Дальше — по требованиям конкретных вакансий: Kafka, Kubernetes, облака, [ИИ-фреймворки](#/page/ai/stack).

## Как готовиться к собеседованию {#interview}

- **Технические вопросы**: Java Core (ООП, коллекции, `equals/hashCode`, исключения, многопоточность, Stream API), Spring (DI, бины, транзакции), SQL, Git, HTTP/REST.
- **Live-coding**: небольшие задачи на коллекции и строки, иногда алгоритмы; говорите вслух, что делаете и почему.
- **Разбор проекта**: будьте готовы объяснить каждое решение в своём портфолио.
- **Поведенческие вопросы**: как решали сложную задачу, как реагируете на критику на ревью, как учитесь новому.
- **Вопросы работодателю**: стек, процессы, ментор для Junior, как проходит онбординг.

:::tip "Неудачное интервью — тоже результат"
Записывайте все вопросы, на которые не ответили, и закрывайте пробелы. После 5–10 собеседований вы заметите, что вопросы повторяются, а уверенность растёт.
:::
