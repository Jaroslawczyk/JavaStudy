Класс можно объявить внутри другого класса. В курсе встречались вложенные `Node` и `Entry` у самописных коллекций и анонимные классы для `Runnable`. Разберём все четыре вида вложенных классов, их отличия и типичную утечку памяти.

## Четыре вида

| Вид | Объявление | Доступ к полям внешнего объекта | Пример |
|---|---|---|---|
| Статический вложенный | `static class Node` внутри класса | ❌ только через ссылку | `Map.Entry`, `Node` в `LinkedList` |
| Внутренний (inner) | `class Node` без `static` | ✅ напрямую | итератор коллекции |
| Локальный | класс внутри метода | ✅ + effectively final локальные переменные | редко |
| Анонимный | `new Interface() { … }` | ✅ + effectively final локальные переменные | обработчики, `Comparator` до Java 8 |

## Статический вложенный класс

```java
public class LinkedList<T> {
    private Node<T> first;

    private static class Node<E> {       // не связан с конкретным LinkedList
        E value;
        Node<E> next;
    }
}

Outer.Nested n = new Outer.Nested();     // создаётся без экземпляра Outer
```

Логически сгруппирован с внешним классом и видит его `private`-члены, но объект внешнего класса ему не нужен. **Выбор по умолчанию.**

## Внутренний класс

```java
public class MyList<T> implements Iterable<T> {
    private Object[] items;
    private int size;

    @Override
    public Iterator<T> iterator() {
        return new Itr();
    }

    private class Itr implements Iterator<T> {      // видит items и size внешнего объекта
        private int cursor;
        public boolean hasNext() { return cursor < size; }
        @SuppressWarnings("unchecked")
        public T next() { return (T) items[cursor++]; }
    }
}

MyList<String>.Itr it = list.new Itr();             // снаружи — через экземпляр (редко)
```

Каждый объект внутреннего класса хранит **скрытую ссылку** `Outer.this`.

:::warning "Утечка памяти через внутренний класс"
Если объект внутреннего (или анонимного) класса живёт дольше внешнего — например, его зарегистрировали как слушатель в долгоживущем сервисе или положили в статический кэш, — он не даёт сборщику мусора удалить внешний объект со всеми его данными. Классика Android: анонимный `Handler` удерживает `Activity`. Правило: если доступ к внешнему объекту не нужен — делайте класс `static`.
:::

## Локальный и анонимный классы

```java
void sortByLength(List<String> words) {
    words.sort(new Comparator<String>() {               // анонимный класс
        @Override
        public int compare(String a, String b) {
            return Integer.compare(a.length(), b.length());
        }
    });
    words.sort(Comparator.comparingInt(String::length)); // сегодня — лямбда/ссылка
}
```

Анонимный класс полезен, когда нужно реализовать интерфейс с **несколькими** методами или унаследоваться от абстрактного класса «на месте». Для функциональных интерфейсов используйте лямбды.

:::note "Что вложено — неявно static"
Вложенные `enum`, `record` и `interface` всегда неявно статические. С Java 16 статические члены (в том числе записи) можно объявлять и во внутренних классах.
:::

:::interview "Вопросы с собеседования"
**Чем статический вложенный класс отличается от внутреннего?** — Внутренний хранит ссылку на экземпляр внешнего класса и может обращаться к его полям напрямую; создаётся только через экземпляр внешнего. Статический не связан с экземпляром.

**Почему анонимный класс видит только effectively final переменные?** — Значения копируются в объект класса при создании; если бы переменную можно было менять, копия и оригинал разошлись бы.
:::
