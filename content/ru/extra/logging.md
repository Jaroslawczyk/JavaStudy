В учебных примерах результат печатают через `System.out.println`. В продакшене так не делают: нужны уровни важности, время, имя потока и класса, запись в файлы или отправка в системы сбора логов (ELK, Loki, Datadog), настройка без перекомпиляции. Для этого есть **логгеры**.

## Фасад и реализация

| Слой | Инструменты |
|---|---|
| **Фасад** (API, которое вызывает код) | **SLF4J** — стандарт де-факто; `System.Logger` (Java 9) |
| **Реализация** (куда и как пишется) | **Logback** (по умолчанию в Spring Boot), **Log4j 2**, `java.util.logging` (JUL), TinyLog |

Код зависит только от фасада, а реализацию можно заменить конфигурацией — библиотеки не навязывают свой логгер приложению.

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class OrderService {
    private static final Logger log = LoggerFactory.getLogger(OrderService.class);

    public void place(Order order) {
        log.info("Placing order id={} items={}", order.id(), order.items().size());
        try {
            payment.charge(order);
        } catch (PaymentException e) {
            log.error("Payment failed for order {}", order.id(), e);   // исключение — последним аргументом
            throw e;
        }
        log.debug("Order details: {}", order);
    }
}
```

С Lombok — аннотация `@Slf4j` на классе вместо объявления поля.

## Уровни

| Уровень | Когда |
|---|---|
| `ERROR` | операция не выполнена, нужна реакция (алерт) |
| `WARN` | что-то пошло не так, но система справилась (ретрай, fallback) |
| `INFO` | ключевые бизнес-события: старт, заказ создан, платёж прошёл |
| `DEBUG` | подробности для разработчика, в продакшене обычно выключен |
| `TRACE` | максимум деталей |

## Правила хорошего логирования

- **Плейсхолдеры `{}`**, а не конкатенация: строка не собирается, если уровень выключен.
- **Не логируйте секреты и персональные данные**: пароли, токены, номера карт, PESEL — это и безопасность, и GDPR/RODO.
- **Исключение целиком** (`log.error("…", e)`), а не `e.getMessage()` — иначе теряется стектрейс.
- **Не логируйте и не пробрасывайте одновременно** одно исключение на каждом уровне — получится пять одинаковых стектрейсов.
- **Контекст через MDC**: `MDC.put("requestId", id)` — значение попадёт в каждую строку лога этого запроса; в микросервисах — trace-id из OpenTelemetry.

## Конфигурация

```yaml
# application.yml (Spring Boot)
logging:
  level:
    root: INFO
    com.example.shop: DEBUG
    org.hibernate.SQL: DEBUG          # посмотреть SQL-запросы
  structured:
    format:
      console: ecs                     # JSON-логи (Spring Boot 3.4+): ecs, logstash, gelf
```

Структурированные (JSON) логи удобны для систем сбора: поля `level`, `logger`, `traceId` индексируются и фильтруются.

:::warning "Log4Shell"
В декабре 2021 года в Log4j 2 нашли критическую уязвимость CVE-2021-44228 (Log4Shell): строка вида `${jndi:ldap://…}` в логируемых данных позволяла выполнить удалённый код. Урок: обновляйте зависимости (Dependabot/Renovate), следите за CVE и не считайте логирование «безопасной» операцией.
:::

:::outdated "System.out и java.util.logging"
`System.out.println` в серверном коде — антипаттерн: нет уровней, нет конфигурации, синхронизированный вывод тормозит. JUL (`java.util.logging`) работает, но неудобен в настройке; в приложениях используют SLF4J + Logback/Log4j 2 (мосты `jul-to-slf4j` собирают логи и из JUL).
:::
