**Связывание** (binding) — момент, когда решается, какой именно метод или поле будет использован при вызове. **Статическое (раннее)** связывание происходит при компиляции, **динамическое (позднее)** — во время выполнения. Именно динамическое связывание делает возможным полиморфизм.

## Динамическое связывание: переопределённые методы

```java
class Animal {
    void speak() { System.out.println("..."); }
}
class Dog extends Animal {
    @Override void speak() { System.out.println("Гав"); }
}

Animal a = new Dog();     // тип переменной Animal, объект — Dog
a.speak();                // Гав — выбирается по РЕАЛЬНОМУ типу объекта
```

Компилятор проверяет, что метод `speak()` есть в типе `Animal`, а какую реализацию вызвать, JVM решает в рантайме по классу объекта (через таблицу виртуальных методов). Все нестатические, неприватные, нефинальные методы в Java — виртуальные.

## Статическое связывание

Решается компилятором по **объявленному типу** переменной:

| Что | Почему статически |
|---|---|
| `static`-методы | принадлежат классу, не переопределяются, а **скрываются** |
| `private`-методы | не видны наследникам |
| `final`-методы | переопределить нельзя |
| **Перегрузка** (выбор между `m(Object)` и `m(String)`) | выбирается по типам аргументов при компиляции |
| **Поля** | не полиморфны, тоже скрываются |

```java
class Parent {
    String name = "parent";
    static String who() { return "Parent"; }
}
class Child extends Parent {
    String name = "child";                      // скрывает поле, а не переопределяет
    static String who() { return "Child"; }     // скрывает статический метод
}

Parent p = new Child();
System.out.println(p.name);     // parent — поле по объявленному типу
System.out.println(p.who());    // Parent — static по объявленному типу (так писать не стоит)
```

## Перегрузка решается при компиляции

```java
static void print(Object o) { System.out.println("Object"); }
static void print(String s) { System.out.println("String"); }

Object x = "hello";
print(x);                       // Object! — выбор по объявленному типу x, а не по значению
```

Сравните: **переопределение** (override) — выбор реализации в рантайме по объекту; **перегрузка** (overload) — выбор сигнатуры при компиляции по типам аргументов.

:::tip "@Override — всегда"
Аннотация `@Override` заставляет компилятор проверить, что метод действительно переопределяет родительский. Опечатка в имени или параметрах (`equals(Car other)` вместо `equals(Object o)`) без неё превращается в незаметную **перегрузку** — и `HashSet` перестаёт работать.
:::

:::interview "Вопросы с собеседования"
**Что такое статическое и динамическое связывание?** — Статическое — выбор метода/поля компилятором по объявленному типу (static, private, final методы, перегрузка, поля). Динамическое — выбор реализации переопределённого метода в рантайме по фактическому классу объекта.

**Можно ли переопределить статический метод?** — Нет, только скрыть (method hiding): вызов определяется объявленным типом, полиморфизма нет.
:::

## Домашнее задание

:::task easy "Override или hide"
Создайте `Parent` и `Child` с одноимёнными полем, статическим методом и обычным методом. Выведите результаты для `Parent p = new Child()`, `Child c = new Child()` и `((Parent) c)`. Заполните таблицу «что вызвалось» и объясните.
:::

:::task medium "Ловушка перегрузки"
Есть `void log(Object o)`, `void log(Integer i)`, `void log(long l)`. Что вызовется для `log(5)`, `log(5L)`, `log((Object) 5)`, `log(null)`? Сначала предскажите (правила: точное совпадение → расширение примитива → автоупаковка → varargs), потом проверьте.
:::

:::task hard "Сломанный equals"
Напишите класс `Point` с методом `public boolean equals(Point other)` (без `@Override`). Покажите, что `point1.equals(point2)` работает, а `list.contains(point2)` и `HashSet` — нет. Объясните через статическое связывание перегрузки, исправьте и добавьте `hashCode`.
:::
