Кроме конструкторов, в Java есть **блоки инициализации** — статические и нестатические. Они редко нужны в прикладном коде, но порядок инициализации класса — любимая тема задач на собеседованиях («что выведет программа?»).

## Статический блок

```java
public class Config {
    static final Map<String, String> DEFAULTS;

    static {                                  // выполняется ОДИН раз — при инициализации класса
        DEFAULTS = new HashMap<>();
        DEFAULTS.put("timeout", "30");
        DEFAULTS.put("retries", "3");
    }
}
```

Класс инициализируется лениво — при первом «активном» использовании: создании объекта, вызове статического метода, обращении к статическому полю (кроме констант времени компиляции). Статический блок удобен для сложной инициализации статических полей и загрузки нативных библиотек.

## Блок инициализации экземпляра

```java
public class Order {
    private final List<String> items;

    {                                         // выполняется ПЕРЕД телом каждого конструктора
        items = new ArrayList<>();
        System.out.println("instance block");
    }

    public Order() { System.out.println("constructor"); }
    public Order(String first) { this(); items.add(first); }
}
```

Используется, чтобы не дублировать общий код в нескольких конструкторах (хотя чаще для этого вызывают `this(...)`) и в анонимных классах, у которых нет конструктора.

## Порядок инициализации

```java
class Parent {
    static { System.out.println("1. static Parent"); }
    { System.out.println("3. instance Parent"); }
    Parent() { System.out.println("4. constructor Parent"); }
}
class Child extends Parent {
    static { System.out.println("2. static Child"); }
    { System.out.println("5. instance Child"); }
    Child() { System.out.println("6. constructor Child"); }
}

new Child();
new Child();   // второй раз — только шаги 3–6
```

Правило:
1. **Статика** — один раз на класс: сначала родитель, затем потомок; внутри класса — статические поля и `static {}` **в порядке написания**.
2. **Экземпляр** — при каждом `new`: вызов `super(...)` → поля и блоки экземпляра родителя (по порядку) → тело конструктора родителя → поля и блоки потомка → тело конструктора потомка.

:::warning "Ловушка: виртуальный вызов из конструктора родителя"
Если конструктор родителя вызывает переопределённый метод, выполнится версия потомка — когда поля потомка ещё **не инициализированы** (там `null`/`0`). Не вызывайте переопределяемые методы из конструкторов.
:::

:::outdated "Код до super() — Java 25"
Раньше `super(...)` или `this(...)` обязаны были быть первой строкой конструктора. С **Java 25** (JEP 513, flexible constructor bodies) перед ними можно писать код: проверять аргументы и **присваивать** поля текущего класса (но не читать `this`). Это решает и проблему из предупреждения выше: поле можно инициализировать до вызова конструктора родителя.

```java
public Child(int value) {
    if (value < 0) throw new IllegalArgumentException();   // до super — Java 25
    this.value = value;
    super();
}
```
:::

:::interview "Вопрос с собеседования"
**В каком порядке выполняются статические блоки, блоки экземпляра и конструкторы при наследовании?** — Статические блоки родителя, затем потомка (один раз). При создании объекта: блоки и инициализаторы полей родителя, конструктор родителя, затем блоки/поля потомка и конструктор потомка.
:::

## Домашнее задание

:::task easy "Что выведет программа"
Не запуская, запишите вывод примера `Parent/Child` выше для двух вызовов `new Child()`. Затем запустите и сверьтесь. Добавьте статическое поле `static int counter = init("counter")` между блоками — где появится его вывод?
:::

:::task medium "Ловушка в конструкторе"
Напишите `Parent` с конструктором, вызывающим `describe()`, и `Child`, переопределяющий `describe()` и печатающий своё поле `private final String name = "child"`. Объясните, почему печатается `null`. Исправьте двумя способами: без вызова виртуального метода и (на Java 25) присвоив поле до `super()`.
:::

:::task hard "Ленивая инициализация класса"
Докажите опытом, что статический блок выполняется не при загрузке программы, а при первом активном использовании класса. Проверьте случаи: обращение к `static final int CONST = 5` (константа времени компиляции — блок **не** выполнится), к `static final Integer BOXED = 5`, вызов `Class.forName("…")`, создание массива `new Config[10]`. Объясните каждый результат.
:::
